# 核对逻辑

## 1. 谁说了算

客户 PAR / PFD → 参数表（定 NOR）→ PVP（引用参数表）→ MOR（执行文件）。ESA、GA 要跟锁定终版 PVP 对齐。

- 上游有、下游没有或写错：报下游。
- 下游比上游宽（MOR 范围超出 NOR，NOR 超出 PAR）：报，严重程度高。
- 下游比上游窄（MOR ★NOR 窄于 PVP NOR）：报，严重程度中。可能有意收紧，写进“需要你确认”。
- 上游自己前后不一（参数表两行同一参数两个数）：放“参数表内部问题”，不要擅自选一个。

## 2. 开工前

1. 取接受修订后的文本：删除的跳过，插入的保留，页眉、页脚、脚注都要读。用 `scripts/docx_lines.py`。
2. 先读版本说明和变更记录。说明里写明是有意改动的（如 Ac₂O 封端后改为直接向合成釜加 DMF 洗涤），不当错误报。
3. 有上一版就先做差：
   - 已经改掉的项，不再报。
   - 改了一处但同句或别节还留着旧字符串的，搜一遍旧字符串。
   - 查回退：上一版改对、这一版又变回去的单独报（αMePhe → aMePhe、10.4 V → 10.39 V）。
4. 读所有批注，按邮箱认客户：`@lilly.com`、`@network.lilly.com` 是客户，不看名字像哪国人。客户批注 `done=0`，且要求补 IPC、改地址或改数字的，正文没有回应前继续报，并写上客户名和日期。客户后来澄清只是问小数位的，不要把前一条猜测写成必须改的数。

## 3. 三方参数核对（PVP / 参数表 / MOR）

1. **从 MOR 原料信息表入手。** 表里按操作号列出物料、V、kg/kg、标准投料量和称量范围。再读正文，因为正文和信息表可能一个改了一个没改。
2. **单位换算。** 参数表的 kg/kg × 树脂投料 = kg；V × 密度 = kg/kg。参数表 NOR 多为 ±5%（个别 ±4%）；MOR 称量范围多为 ±3%，1 V 冲洗为 ±2 kg。
3. **★ 句逐条比。** 抽出 MOR 所有 ★ 句和 “within the Normal Operating Range (NOR)” 句里的数，与 PVP CPP 表逐条比。PVP 表头写 “NOR (MOR)” 时，两边应完全相同。
4. **CPP 清单两向比。**
   - PVP 每个 CPP，问 MOR 在这一步有没有控制点和记录点（例：溶解夹套温度在 PVP 是 CPP，MOR 溶解阶段没控温）。
   - MOR 标 ★CPP 而 PVP 没有的，也要报（例：DMF 总用量、DIC 加料温度、哌啶溶液温度）。
5. **按氨基酸逐个核。** 偶联温度、偶联时间窗口和 NMT、脱保护时间、洗涤体积和次数、再溶胀体积、IPC 方法和判据，逐个氨基酸核，不能用“标准 AA”一句带过。
6. **对不上的行先判断再问。** 参数表行名与 MOR 操作号对不准时，先给出判断和把握（高 / 中 / 低），放进对应关系表；把握低的放进“需要你确认”。
7. **算产量前先找公式。** 先看 MOR 的理论产量公式和取代度标准，再算。肽树脂产量随取代度变化，不等于投料 × 收率。

## 4. MOR 单独审

MOR 一般写明“本记录以中文为准”，所以中英数字不一致必须报：现场会按中文执行。

先跑 `scripts/mor_auto_checks.py MOR.docx --resin <树脂 kg>`，它会列出候选。逐条人工判断，属实的才写进硬伤表，同类合并成一行。自动检查覆盖：

| 检查 | 典型命中 |
|---|---|
| 中英数字不同（同一行 “英文/中文”，或英文段紧跟中文段） | DIC 英文 2.20 eq、中文 2.00 eq；搅拌 5±2 min 对 5±5 min；wash 1 对 洗涤2 |
| 中英引用步骤号不同 | documented in Ins3.1.3 / 记录于3.2.1 |
| 占位符 | ★ 限 `XoC`、`xx oC` |
| ★ 限宽于本节设定，或超温预警落在 NOR 外 | 偶联 ★13–37 ℃（抄了封端 PAR）；Leu12 ★8–32 ℃ |
| 时间窗口上限超过 NMT；全文多个 NMT 值 | 13 h ≤ total ≤ 28 h 对 NMT 840 min；840 / 841 混用 |
| 步骤号前缀与所在节不符 | 3.28 节里出现 3.25.8 |
| 页眉页脚 MOR 号不是本项目 | 10 个页眉写 MOR-TJ414001901.04 |
| 标准量不在称量范围内，或范围不对称、过宽 | 419.04 kg 配 440.34–467.58 kg；432.54 ~ 4459.30 kg |
| confirm 译成“执行” | “工艺性能执行”、“设备执行”，成批出现 |
| 英文拼写 | diaphragmgm、soulution、additon |

脚本查不到、要人工看的：

- 设备清单：材质与 ESA 是否一致（激活罐是哈氏合金不是不锈钢；手套箱数量和编号）；操作号是否对得上正文。
- IPC 表：方法号、判据颜色与方法一致；客户要求的 IPC 是否都在；取样步骤引用的记录表是否正确（谷氨酸取样不能引用茚三酮记录）。
- 原料信息表与正文体积不一致（信息表 3.16.4 仍是 8 V）。
- 批量和产量：页脚、版本说明、公式算出的范围三者是否一致。
- 同一节先写 “NLT 600 min”，又写“不超过”。
- 误译：Particulate Drain、cabinet 与“保温箱”等，要读上下文判断。
- 步骤标题的次数：英文 wash 1、中文“洗涤2”（3.5.9、3.11.9、3.31.9）。自动检查能抓到，仍要人工对照相邻步骤确认哪边对。
- 不合格处置句里的 NMT 是否抄错：Phe23 写 841 min，3.10.5 和 3.18.5 本步上限是 840 min，处置句仍写 841。
- 超温预警跟本步设定比，不跟本节别的温度比。3.17.7 控温 20±5 °C，预警却是 22–28 °C，目标 20 °C 会一直报警。
- 同一个指令号是否用于两个操作。3.44.1 既是洗涤又是取样；3.43.5 既是洗涤又是 IPC。表头重复的“内部温度”不是第二个操作。

## 5. PVP 检查清单

- CPP 表的 Target 栏写的是实际投料，不是 PAR 下限（“NLT 8.73” 应为 8.73）；NOR 下限不得低于 Target 栏的 NLT 值。
- 单位：kg 与 kg/kg、g 与 kg、V 与 kg/kg 换算。
- 同一参数在正文、CPP 表、附录里只能有一套数；设备号、方法号、质量标准号同理（Val 不能用 Arg 的 SP 号）。
- 文件号前后一致：PAR 报告号、稳定性方案号、变更号、下一步产物号；章节和表格的交叉引用指向正确。
- 范围与策略：没有放行标准的中间体不写 CQA / release specification。
- IPC 判据与方法一致（茚三酮阴性为 yellow to light pink，不是 colorless）。
- 方法表不能是空表而正文在引用。
- 供应商地址写到城市、省和国家，与 Table 2、VMP 一致。
- 被误改的段落：公司名、产品句被改坏。

## 6. ESA 检查清单

- 工艺描述与终版 PVP 逐步对齐：重复次数（Perform this operation N times）、体积、kg/kg、温度、时间。终版没写的旧值（两套甲苯 V）要删。
- 设备评估表：理由栏是否抄错物料（DMF 的句子抄到 DIPEA 行；甲苯行写 MTBE）；材质缩写是否存在（306 SS、31603）；High 和 Low 不能同时勾。
- 仪表表的 MOR / NOR 与工艺一致，单位正确（g 和 kg）；转速、流量不要套用别的釜。
- 章节编号不重复、标题与内容设备一致；设备容量与设备表一致。
- 资质日期不能晚于文件日期。
- 中间体编号和片段编号不要混用。

## 7. GA 检查清单（以同系列已定稿 GA 为格式模板）

- 句式与模板一致：先写没有变的部分，再写 “Only the following optimization items”。不能先写“核心工艺没变”，后面又列出工艺变更。
- 摘要、正文、结论三处的类数、设备号、方法号一致。
- 句子是否完整：to 后面缺目的设备；缺谓语。
- 物料号、方法号的位数（YL00033 与 YL000336）；变更号重复片段。
- 质量标准两列对比时，限度、单位（ppm）、上下限是否成对出现；不是有意放宽的要补回。
- 材质不是原料：写 material of construction，不写 primary raw material。
- 职务、签署人在评估组和签署页一致。
- 拼写和语法：Assey、rang、star（start）、the the、has/have。

## 8. 报什么，不报什么

报：
- 单位错；同一文件里两套数。
- 文件之间不一致的 CPP、投料、时间、温度、次数。
- 质量标准号张冠李戴；文件号前后不一。
- 客户要求的 IPC 仍缺。
- 会执行错的判据；Target 栏写成 PAR 下限。
- MOR 中英数字不同；占位符；★ 限抄错。

不报：
- 只差 25 与 25.0、空格、°C 写法。
- 终版反复保留、不影响执行的语病（除非用户要求“从头捋”）。
- 客户已标 done 的提问。
- 版本说明里写明的有意改动。

## 9. 第二遍，以及对照终版之后

清单和自动检查跑完后，合上清单，按操作顺序再读一遍。每一步只问三句：按中文做会得到什么数；这个数和上游文件是不是同一个；指令号在全文是不是唯一。新发现的追加进同一张 Excel。

这一遍发现的检查点，写回本文件和 `GROK-PROMPT.md`，两处用同一句话。

用户给出人工改过的终版时同样处理：对接受修订后的文本做差。终版改掉的不再报；终版改了一处、别处还留旧字符串的要报；上一版改对、终版又改回去的单独报。终版实际采纳的规则写进本文件、项目事实和 `GROK-PROMPT.md`，并随仓库提交。

## 10. 交付前自查

1. 每条“内容”都通过 `write_review_xlsx.py` 校验，不能有 `\xa0`、跨段、找不到。
2. 每条“问题与改法”都写了各方数字和改成什么。
3. 算过的数重新算一遍，写出算式；拿不准的写“请确认”，并放进“需要你确认”。
4. 同类错误合并，列全位置。
5. 回头看本轮之前自己报过的项：被版本说明或新证据推翻的，删掉，并在回复里说明。
